# 只做中国业务：数据源怎么买、怎么接、合同要写什么

> 适用场景：货代只做**中国起运**（中国出口）的生意，只需要中国相关的贸易数据。
> 调研日期 **2026-10-21**。所有价格都标了来源等级：**官网现价** / **二手来源** / **未核实**。
> 价格会变，签约前必须重新询价——本文档的作用是让你知道**该问什么**，不是替你砍价。

---

## 一、先分清两件事：你要的是「谁在出货」还是「谁在买货」

这两个问题的数据源完全不同，买错了就是白花钱。

| 你要找的人 | 数据形态 | 谁能提供 | 免费吗 |
|---|---|---|---|
| **中国出口商 / 工厂**（国内货主） | 中国出口报关记录：企业名、HS、金额、数量、目的国、口岸、日期 | 国内持牌数据商（特易、环球慧思、腾道、国贸通等） | **不免费**，官方不公开企业级明细 |
| **海外买家**（从中国进口的外国公司） | 目的国进口提单：进口商名、发货人（常是中国出口商）、HS、货量、港口 | Panjiva、ImportGenius、ImportYeti | **部分免费**（美国免费） |
| 行业大盘（做不做这个品类） | HS × 国别 × 月份的金额与量 | 海关总署统计、UN Comtrade | **免费** |

**如果你只做中国起运的整柜海运，优先级是「海外买家 > 中国出口商」**：决定用哪家货代的是收货人（或其在中国的采购代理），而且海外买家的名单有免费源可以先用。中国出口商名单用来做**交叉验证**（这家真的在出货吗、走哪条航线、多大量），不必作为第一笔采购。

**只买中国额度怎么理解**：国内数据商按「国别模块 / 数据版本 / 席位数」报价，你可以只买「中国出口」这一个模块，不买全球库。这是省钱的关键，签合同前明确写「仅中国出口模块」。

## 二、Panjiva（S&P Global）怎么获取

### 2.1 它是什么

S&P Global Market Intelligence 旗下的供应链情报产品，数据来自各国海关 / 提单记录，做成可检索的企业画像。它的中国数据不是自己从中国海关拿的——公开报道里 S&P 明确说过，中国数据来自与 **ETCN（Export to China）** 的合作，而 ETCN 的数据「基于中国政府提供给它的数据」。当时（2014 年报道）覆盖约 **37.5 万家**中国进出口企业。

> 这个数字是 2014 年的官方口径。**POC 时必须重新确认当前覆盖**，别拿十年前的规模做采购依据。

### 2.2 获取路径（按实际可行性排序）

| 路径 | 怎么做 | 适合谁 | 周期 |
|---|---|---|---|
| **销售对接（主路径）** | S&P Global 官网 Contact Us → 说明「Panjiva Supply Chain Intelligence，中国出口/进口数据，N 个席位」→ 销售安排演示 → 签 Data Subscription Agreement | 企业采购 | 通常 6–12 周（含法务、安全问卷、采购流程） |
| **Marketplace 数据集** | `marketplace.spglobal.com` 上 Panjiva 数据集页需登录后申请，交付形态含 API / Snowflake / feed | 已有 S&P 合同、要走数据管道 | 需先有账号与合同 |
| **网页版订阅** | 直接在 Panjiva 平台按席位订阅 | 小团队快速上手 | 较快，但功能受限 |
| **WRDS（学术）** | 高校通过 WRDS 访问 Panjiva Supply Chain Intelligence | 高校 / 研究 | 仅学术用途，不能商用 |

**没有公开定价页。** 网上流传的「高级账户 $299/月起」是第三方文章的说法（`未核实`），不要拿它做预算——企业级报价通常按**数据范围 × 席位数 × 使用方式（网页 / API）× 合同年限**定，年付有折扣。

### 2.3 试用/POC 必须做的三件事

1. **反查准确率**：拿 10 家你自己认识的客户（中英文名各 5 家），看能不能搜到、货量对不对、目的国对不对。搜不到就是搜不到，别信「我们覆盖全球」。
2. **问「最近一条记录的日期」**，不要问「你们每天更新吗」——后者任何人都会答「是」。按国家差异极大，美国/巴基斯坦周级，多数国家滞后 1–2 个月。
3. **确认字段**：有没有收货人名称、有没有联系方式、HS 到几位、金额是报关价还是估算。

## 三、中国侧的数据源（只买中国额度时看这一节）

### 3.1 官方免费：只有汇总，没有企业名

| 来源 | 地址 | 能给什么 | 给不了什么 |
|---|---|---|---|
| 海关统计数据在线查询平台 | `stats.customs.gov.cn` | 按商品 / 贸易伙伴 / 贸易方式 / **收发货人注册地** 组合查询的进出口额与量 | **任何企业名称** |
| 海关统计月报 | `cws.customs.gov.cn` | 月度进出口商品国别总值表、重点商品量值表 | 企业级明细 |
| UN Comtrade | `comtrade.un.org` | HS 6 位、按国别与年份的贸易额 | 企业级明细 |
| 各省海关 / 商务厅 | 各关区网站 | 本省外贸简报、重点商品 | 企业级明细 |

**关键点**：官方查询平台里有「收发货人注册地」这个维度，能查到「某省某商品出口到某国多少钱」，但**永远查不到是哪家公司**。所以「免费能不能替代商业数据」的答案是：做行业判断可以，做客户名单不行。

### 3.2 只能查自己：单一窗口 / 电子口岸

国际贸易「单一窗口」、中国电子口岸可以查**本企业自己的**报关单、舱单、税单。这是企业自查通道，**不能查别人**。任何声称能「用单一窗口查竞争对手出口记录」的说法都不成立。

### 3.3 商业数据商（买中国出口模块）

| 供应商 | 定位 | 价格量级 | 来源等级 |
|---|---|---|---|
| **腾道** | 主要做中国数据 | 约 2 万/年起 | 二手来源 |
| **国贸通** | 中国 + 部分海外 | 3 万起，全库约 5 万 | 二手来源 |
| **环球慧思** | 老牌，覆盖广 | 4 万起，详细版 5–6 万 | 二手来源 |
| **特易（Tradesns）** | 代理数据为主，覆盖略少 | 4 万起，邓白氏联系方式另收费 | 二手来源 |
| **外贸宝 / 跨境魔方** | SaaS 化，性价比路线 | 数千至数万/年 | 二手来源 |

> 以上都是聚合文章口径（知乎、搜狐等），**只能当量级**。同一家对不同客户报价差异很大，按「国别模块 + 席位数 + 年限」谈。

**买中国模块时必问的五个问题**：

1. 中国出口数据**从哪来**？（报关单 / 提单 / 目的国反查）有没有**授权链条**书面说明？
2. 最近一条记录的**日期**是多少？月度还是周度更新？断更过吗（腾道曾被提到「断更后国外数据覆盖少几个国家」）？
3. 企业名是**中文注册名**还是英文申报名？能不能按统一社会信用代码去重？
4. 有没有联系人/邮箱？——**大概率没有**，见第五节。有的话是自采还是外购，合法性依据是什么？
5. 能不能先给 **50 条样本**（含日期），让我拿已知客户验证准确率？

## 四、合同必须写进去的八条

数据采购的坑几乎都在合同里，不在功能里。

| # | 条款 | 为什么必须写 |
|---|---|---|
| 1 | **数据来源合法性承诺 + 违约赔偿** | 供应商的数据若被认定来源不合法，你是下游。没有这条，风险全在你 |
| 2 | **授权链条说明**（谁授权给谁、期限） | 「我们合法」不是证据，「某海关/某持牌机构 → 供应商 → 你」才是 |
| 3 | **更新时点 SLA**（不是「定期更新」） | 写明「每月 X 日前提供截至上月 Y 日的数据」，否则断更无法追责 |
| 4 | **字段级来源**（哪个字段来自哪张单据） | 出问题时能定位；也防止「估算金额」被当成报关金额用 |
| 5 | **不得转售 / 二次分发** | 你把它灌进自己的系统给客户看，可能已经违约 |
| 6 | **删除与退出**（合同终止后多少天内删除） | 与《个人信息保护法》的删除义务对齐 |
| 7 | **审计配合**（监管问询时供应商须提供证明） | 出事时你需要上游配合，不是失联 |
| 8 | **调价与续约规则** | 第二年翻倍的故事很常见 |

## 五、中国海关数据的字段现实：**没有邮箱**

这是整件事里最容易被忽略、也最影响 ROI 的一条。

一条中国出口报关记录通常长这样：

```
出口商 | 采购商 | HS编码 | 商品 | 金额 | 数量 | 起运港 | 目的国 | 日期 | 贸易方式 | 企业性质
```

**它没有的东西**：联系人、职位、邮箱、电话、官网。

这意味着：

- 买回来的名单**不能直接发信**，必须先补联系方式（企业官网、工商信息、展会名录、领英、B2B 平台公开页）。
- 「买了 1 万家客户」和「能给 1 万家发信」之间，隔着一整个富化环节。
- 富化本身有成本：人工找一家约 1–3 分钟，1 万家就是 200–500 小时。

系统里这件事现在是**显式**的（见第六节）：导入就告诉你「这批 0 条可发信」，而不是等你在起草时一条条撞墙。

## 六、系统里已经接好的部分

| 能力 | 位置 | 说明 |
|---|---|---|
| 导入中国海关导出 | `POST /api/v1/prospects/import` | 支持中文表头：出口商 / 采购商 / HS编码 / 金额 / 数量 / 起运港 / 目的港 / 日期 |
| **选边** | `entity_side: exporter \| importer` | 一行两个主体，卖中国起运就选 `exporter`，卖进中国就选 `importer`；另一边存为 `counterparty` |
| **可发信统计** | 返回 `contact_gaps` | `{emailable, no_email, no_contact_name}`；全都没邮箱时返回 `note` 明确说明 |
| 数据时点 | `data_as_of` + `evidence.age_days` | 缺失 / 不可解析 / 未来日期一律 `null`，不给好看的 0 |
| 单条核验 | `GET /api/v1/prospects/{id}/evidence` | `contactable`、`missing_contact_fields`、`shipment_facts`（HS/金额/日期原样保留） |
| 评分与发送门禁 | `POST /prospects/{id}/score` + 发送时四道门 | 导入 ≠ 合格；未评分 / 低分 / 未审批 / 无合法依据都发不出去 |

### 跑一遍（活服务）

```bash
curl -X POST http://localhost:8100/api/v1/prospects/import \
  -H 'X-Demo-Tenant: tenant-demo' -H 'X-Demo-User: u1' -H 'Content-Type: application/json' \
  -d '{
    "source": "tradesns",
    "data_origin": "cn_export_2026",
    "contract_ref": "TS-2026-0142",
    "data_as_of": "2026-09-30",
    "entity_side": "exporter",
    "format": "csv",
    "default_lane": "Ningbo -> Los Angeles",
    "content": "出口商,采购商,目的国,HS编码,金额,数量,日期\n宁波海隅机械有限公司,Meridian Trading LLC,United States,8479.89,182000,24,2026-09-28\n"
  }'
```

返回里会直接看到 `contact_gaps: {emailable: 0, no_email: 1, ...}` 和一句说明——
**这就是这批数据真实的价值：有公司、有货量、没有联系方式。**

## 七、法律边界（必须知道的三条）

1. **企业名称 + 交易记录属于经营信息，不是个人信息**，但**联系人姓名、邮箱、电话是个人信息**，受《个人信息保护法》约束；用于营销需要有合法性基础（同意 / 已公开 / 履行合同必需等），并给退订通道。
2. **不得爬取**。阿里国际站、企查查、领英的用户协议普遍禁止抓取；爬来的数据既不能证明合法来源，也可能触发《反不正当竞争法》。
3. **不得转售 / 公开展示**。买来的数据用于自己获客，与把它做进对外产品是两件事，后者通常需要单独授权。

本仓库的对外触达已经强制：人工审批 + 合法依据 + 频率上限 + 评分下限，四道门在 `app/services/prospecting.py`，
对照表见 [`OUTREACH_COMPLIANCE.md`](OUTREACH_COMPLIANCE.md)。

## 八、结论：只做中国，钱该花在哪

**推荐顺序**（不是理论最优，是最不容易浪费钱的顺序）：

1. **第 1 个月：0 元。** 用 ImportYeti 免费找 20 家美国进口商（有公司名、有提单），导入系统 → 评分 → 对 ≥70 分发 20 封开发信 → 记回复率。同时用 `stats.customs.gov.cn` 确认你选的品类在目标国是涨是跌。
2. **第 2–3 个月：仍不买。** 把回复率做到能看（≥5% 才继续）。回复率不行，问题在报价速度 / 清关能力 / 舱位保障，换数据源解决不了。
3. **第 4 个月：买中国出口模块（2–4 万/年）。** 此时你已经有转化率基线，能算出「每条线索值多少钱」，谈判时不会被报价牵着走。买之前用 50 条样本验准确率。
4. **Panjiva：只在需要多国买家名单时买。** 它最贵、采购周期最长；只做中国起运、又主要找美国买家的话，ImportYeti + 国内中国模块已经覆盖了大部分需求。真要买，走销售对接 + POC，别按网传价格做预算。

**一句话**：数据买的是「谁可能存在需求」，不是「谁会回你」。前者 2 万一年能买到，后者只能靠报价速度、清关能力和舱位保障——那是主流程在解决的事。

## 九、本文档的方法与局限

- Panjiva 的定价、中国覆盖规模、更新频率**没有公开权威数字**，本文只给获取路径与必须问的问题，不给假价格。
- 国内四家的价格来自聚合文章（知乎/搜狐/百家号），属二手来源，只能当量级。
- 「中国数据来自 ETCN」依据的是 2014 年 Logistics Management 的报道，当前合作状态需向 S&P 确认。
- 没有覆盖：Gitee/中文技术社区、各数据商的实际合同文本、海关「电子舱单保密」对中国出口侧的影响。
